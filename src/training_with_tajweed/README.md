# V2: vowelled transcription and expert-supervised tajweed/pronunciation

**Distinct tasks:** `normalized_with_harakat` is a *text transcription target*
derived from the Qālūn Uthmani source. It preserves observed fathah, kasrah,
dammah, tanween, shaddah, sukun, madd and dagger alif while removing ayah
numbers/waqf and annotation dots. It cannot tell whether the student produced
those features correctly. Training a diacritized Whisper adapter **is not a
tajweed detector**. Do not label all original reciters as `no mistakes` without
expert listening/verification.

The metadata of all four reciters includes this field. To reproduce it after
new data collection:

```bash
python src/training_with_gpu/add_harakat_metadata.py
```

This preserves raw Uthmani and unvowelled `text_asr_normalized` intact. If
metadata is regenerated by another builder, rerun this step before V2.

## Stage 1 — diacritized ASR (experimental)

With the RTX 5070 environment described in the GPU README:

```bash
python src/training_with_tajweed/train_diacritized.py --model base --output-dir runs/v2_diacritized --dry-run
python src/training_with_tajweed/train_diacritized.py --model base --output-dir runs/v2_diacritized
```

The objective and evaluation for this stage keep the *reference diacritics*;
WER/CER are not interchangeable with unvowelled V1 results. Uthmani symbols
and orthographic dagger alifs are writing conventions; acoustic vowel duration
and tajweed are not recoverable from these transcripts alone. Compare with
qualified teachers and independent speakers before using V2 output to correct
a learner.

## Stage 2 — properly labelled detection

```bash
python src/training_with_tajweed/make_annotation_manifest.py --output runs/v2_review.jsonl
```

It writes paths, vowelled reference and `errors: null` to a review manifest.
Experts should listen and replace each null with `[]` for *verified correct*
audio or events like:

```json
{"type": "tajweed", "start_sec": 1.20, "end_sec": 1.65}
```

or `"type": "makhraj"` for a reviewed articulation error. Set `reviewer`
to a nonempty reviewer identifier. These **time spans refer to the WAV**, not
the original full-surah times. Capture type, location and severity in a richer
annotation specification before deploying a model; hold out entire speakers
and recording conditions, and measure inter-annotator agreement. Generate
paired controlled correct/incorrect pronunciations from *consenting human
readers*, then review every example. Wholly missing words/ayahs need separate
V1 labels, not tajweed labels.

Once a real detector produces predictions JSONL with matching `audio_path`
and `errors` lists of the same schema, score one-to-one temporal matches:

```bash
python src/training_with_tajweed/score_tajweed.py --annotations runs/v2_reviewed.jsonl --predictions runs/v2_predictions.jsonl
```

The output includes event precision/recall/F1 and the alert rate on verified
clean clips. **No fully supervised tajweed classifier or measured tajweed
accuracy exists yet.** It cannot be responsibly trained without the missing
expert event annotations. Style (murattal versus mujawwad), microphone,
prolonged vowels and reciter identity are confounders, not mistakes.

Synthetic voice cloning is discussed in the GPU README. Keep any XTTS
experiments separate, explicitly synthetic and outside the blind test set.
